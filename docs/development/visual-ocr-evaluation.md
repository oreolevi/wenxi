# 水印、手写与印章识别验证记录

验证日期：2026-11-04。范围为六页虚构材料的技术探测，未变更应用功能或部署。

## 结论

现有 MinerU 链路对本组水印和手写数字已有一定处理能力。当前最明确的缺口是印文识别、印章区域的语义标注，以及盖章覆盖正文时的识别可靠性。暂不建议增加一个默认执行的“去水印”步骤。

## 材料和方法

- 业务字段：虚构申请单位、金额和日期。独立印章使用另一家虚构公司的名称，避免从正文公司名推定印文。
- 六页均为栅格 PDF，无可提取文字层。生成器、评分清单和固定数字样本可复现，见 [验证工具说明](../../mineru-local/benchmarks/README.md)。
- 本次输入 PDF 的 SHA-256：`c6a59a96f520db9db97fded669439be3a9c016fbdb83108f09eae2e9151710c6`。字体和图像库版本变化可能影响生成文件的摘要，复验时应同时保留清单。
- 手写数字来自 MNIST 测试集，按金额和日期拼接。未测试中文手写、自然整行书写、连笔或签名。
- 同一份六页 PDF 分别调用 MinerU 官方托管 `vlm` 与 `pipeline`，两份返回的版本标识均为 `3.4.4`。
- 再将 VLM 的实际识别结果交给现有 DeepSeek 字段链路。字段要求仅包含字段名称，预期答案不传给识别或模型服务。
- 正文字段共 15 项，印文另计 4 项；按页检查文字命中。规范化仅统一全半角、空白和千分位，不纠正错误字符。

## 实测结果

**清晰印刷、浅色水印、密集水印**：两种模式的三个正文字段均命中。水印词未进入适配后的正文。仅说明这两种水印样例未影响目标字段，不能推断所有水印都可忽略，也未生成去水印图片。

**手写数字拼接**：VLM 的三个字段均命中；pipeline 的单位和金额命中，日期识别为 `2026-/1-04`，预期为 `2026-11-04`。单个样例不能证明两种模式的普遍优劣，也不能代表中文手写能力。

**独立虚构印章**：两种模式都将印章归入图片，正文布局未提供可用的完整印文。单位和印章类别均未命中。

**印章覆盖正文**：VLM 保留了单位和金额，日期缺失；pipeline 保留单位，金额误读为 `1286ρ.00`，日期缺失。两种模式都未读出完整印文。遮挡条件下，引用校验只能证明字段引用了识别文字，不能证明它与原图一致。

本组正文字段文字命中分别为 VLM **14/15**、pipeline **12/15**，印文字段均为 **0/4**。这些分数仅用于本组样例对照，不作为生产准确率。

- VLM 中存在的 14 个目标正文字段均提取出预期值，并通过现有文字引用校验，状态仍为待人工核验。
- 被印章覆盖而漏识的日期返回缺失，没有补入评分基准中的日期。
- 两个印章样例的“印章名称”均保留为 `visual_required`，未以正文单位名替代印文。
- 两页印章在提供方返回中是图片块，当前文字适配不产生对应的 `seal` 文字块；这两项视觉字段没有可用的印章区域引用。
- 检查了返回引用的页码和归一化坐标范围。未进行端到端浏览器原图定位验收，也未做区域重叠精度测量。

## 建议实施顺序

1. **先补印章区域与印文识别。** 以原图为依据，保存印章区域、页码、识别印文和识别来源；正文公司名与印文分别展示。候选专项识别链路需另用获准脱敏的真实扫描件或逼真合成材料验收。
2. **水印先做干扰控制。** 保留原图，仅在派生识别副本上尝试颜色或背景抑制，并对比正文漏识情况。暂不默认删除原图中的水印和印章。
3. **手写按业务范围补测。** 先验证常见的手写金额、日期、姓名和短备注，再判断现有引擎是否足够。签名内容识别与签名身份核验分别立项。
4. **重复文字块去重另做验证。** 本轮密集水印样例不等于重复 OCR 块测试。后续去重应结合页码、坐标和文本，保留不同位置合法重复的业务文字。

这些能力适合在现有能力组件和字段核验流程中逐步接入，不需要再增加一套工作台。原图与派生图的坐标必须保留映射关系。
