# 协作与部署

## 仓库范围

仓库存放源码、依赖清单、使用文档及虚构测试样例。模型、密钥、上传材料、历史结果、Studio 草稿和已发布服务数据由运行环境单独保存。

首次克隆按根目录 [README](../../README.md) 选择运行模式。UI 开发可先使用纯前端演示，不需要识别服务。真实功能联调使用自己的虚构材料和服务端模型配置。

## 协作流程

1. 外部参与者先 Fork，受邀协作者可在原仓库操作；从更新后的 `main` 创建功能分支。
2. 完成变更及相应检查，不提交依赖目录和运行数据。
3. 提交 Pull Request，说明问题、变化和验证方式；UI 变更附虚构材料截图。
4. 评审、检查通过后合并，再由维护者更新试用环境。

参考 [贡献说明](../../CONTRIBUTING.md)。CI 检查前后端测试及前端构建，不使用生产密钥，不发起付费模型请求，也不自动部署服务器。

## 共享试用环境

当前云端版本通过 HTTPS 和共享账户保护入口。网页调用文析后端，后端调用 MinerU 托管 API 与 DeepSeek；原图、校正页面、Markdown、配置和历史保存在服务器的持久化目录。

调用记录和统计设置使用 SQLite；服务、场景、版本及历史快照仍使用 JSON 文件。当前没有个人账户、角色权限或租户数据隔离。共享账户下的服务端数据为共享数据。

部署配置及回退流程见 [云端部署](../../deploy/live/README.md)。页面校正和原图映射已纳入云端流程，不需要在轻量服务器上安装完整 MinerU 或大模型权重。

## 数据与代码

代码仓库不会同步本机与线上的业务数据。服务或场景迁移应单独设计导出、审核和导入流程，不应复制完整 `.runtime` 目录。

线上密钥只存放在服务器环境文件中；开发者使用自己的本机配置。不要将密钥、访问密码、真实文档、识别结果或包含这些内容的截图粘贴到 Issue、Pull Request 和日志中。

后台代码更新后，应在无活动任务时重启服务；前端需要重新构建。生产发布独立进行，保留原镜像和数据卷，先验收虚构样例再切换版本。

## 本机 MinerU 与远程识别

本机完整版本使用 basic ONNX 模型完成 Studio 快速 OCR。`WENXI_MINERU_API_URL` 仅覆盖本机版的部分 CLI 解析，不能代替云端模式。

云端版本设置 `WENXI_RECOGNITION_BACKEND=mineru-cloud`，统一适配通用解析、全文和 Studio。页面方向模型、倾斜校正及原图映射在业务后端完成，OCR 与版面识别交给 MinerU 托管服务。

## 连接故障

`DeepSeek 连接失败或响应中断` 表示模型请求连接或读取失败，不等于 OCR 失败。检查网络、代理和模型服务连通性。服务端已受理但未返回时，用量可能未知，平台不会自动重试付费请求。

`.runtime/wenxi-model-usage.jsonl` 仅记录调用编号、时间、模型、耗时、用量和筛选后的错误信息，不记录密钥、提示词和文档正文。关闭任务后，已保存的原文与核验结果可从历史记录恢复。
